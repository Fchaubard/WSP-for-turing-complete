# Frozen iterative WSP protocol, version 1

This protocol was fixed before sending the first revision request. Use all 60 archived same-objective first responses (87 task/size/seed settings per information arm). Round zero is the literal original vector. Never change dimensions, operators, initial draws, seed, targets, or original information condition. Each new request is an independent ephemeral request to the existing hosted gpt-6-astra alias at medium effort. It receives the original prompt, including the original arrays, and the selected incumbent for each currently active size. The archived first response is used as initialization for the feedback process. Prohibit tools. Default concurrency 12 across independent calls and 300 seconds per call. No automatic retry. A failed or timed-out request counts as an unsuccessful proposal for every active size in that request.

Feedback uses only the original training examples and a new fixed central development set. For Fibonacci and triangular numbers the development indices are 9 through 16, strictly after the training indices 0 through 8. Indices 17 through 32 are reserved. For the other tasks take 256 new i.i.d. central examples per task and seed using numpy.random.default_rng(7810000 + 10000 * i + seed), where the zero-based task index i is in this order: square, sin, selfpower, tanh, add, subtract, sum, sort, fib, tri. Generate coordinates uniformly on [-3,3] except [0,3] for self-power. Array shape is (256,) for scalar functions, (256,2) for arithmetic, (256,6) for running sum, (256,4) for sorting. Both conditions and all widths see the same development examples within a task/seed. The main study's fixed 2,048 central and outer samples stay untouched by the revision process. Report each incumbent's number of whole exact examples, number of examples, raw root mean squared error and scaled half mean squared loss on each split. The latter is one half the mean squared error after each scalar prediction error is divided by max(1, |its target|). For each size and split, show at most three examples with the largest maximum absolute scaled coordinate error. Show input, all target and predicted coordinates and maximum scaled error. Break ties by original row order. After full exactness on just one split, omit zero-residual diagnostic examples from that split. Do not reveal any outer input, output, score or other comparison arm.

For each still-active size, request one complete vector (arrays in listed order). Accept it if its pair (development loss, training loss) is lexicographically smaller than the incumbent's pair. Compare the actual binary64 scores with strict inequalities. Ties retain the incumbent. For a finite vector with any nonfinite training or development prediction or loss, reject the vector. Invalid lengths, nonfinite parameters, nonnumeric JSON entries or a non-response count as unsuccessful proposals. A response with the wrong total number of arrays invalidates every proposed size. At each size stop when the incumbent is exact on every training and development example, after two consecutive rejected proposals, or after three attempted revision rounds, whichever occurs first. A previously accepted proposal resets the rejection count. Stop before a first revision when round zero already satisfies the exactness condition. Active sizes in a common original request may stop independently.

Archive each request prompt, raw final reply when present, request metadata or terminal error, original case ID, current active sizes and resulting per-size decisions. The feedback driver must not read outer scores or generate outer coordinates. Evaluate the selected weights on the outer set by separate code after freezing their final selection. Comparisons are within information arm and original fixture, with round-zero results retained. This experiment measures bounded feedback outcomes; its rule does not assert convergence. The reused development set provides feedback and selection, so it is not a clean held-out endpoint for the iterative method.
