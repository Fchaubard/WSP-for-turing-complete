# Paired endpoints for the nonconvex benchmark

The primary comparison uses ten tasks, 29 task-specific architectures and three starts per architecture. A setting is one task, architecture and seed. Running sum contributes two architectures after the memoryless convex case is excluded. Each of the other nine tasks contributes three. A positive midpoint-convexity violation of the exact real training objective determines inclusion, independently of which solver performed best. These 87 paired settings represent 75 distinct training objectives: the Fibonacci and triangular tasks repeat the same observed indices across starts at each size. Multiple sizes also share observations and writer prompts. We treat the counts as descriptive and compute no independence-based significance test.

Astra received the training inputs and outputs, architecture, initial weights, domain and common primary training loss. The Formula and examples condition also received the target rule. Both literal conditions submit their first returned array. The comparator methods are 800 full-batch Adam updates followed by BFGS and trust-region least squares from the same Xavier weights. The gradient solvers use the endpoint selection and polishing rules of their own prespecified solver. Neither held-out split participates in choosing a checkpoint. The eight existing task graphs use fresh writer responses from `focus/objective`. Addition and subtraction use separate, newly trained fully connected rectifier graphs in `focus/arithmetic`. No older writer array enters a primary comparison.

`endpoints.csv` contains the predicted-error measurements. Primary methods are `examples`, `formula`, `adam_bfgs` and `ls_xavier`. The method `xavier` is their shared initial checkpoint. The prefix `archived_` identifies an earlier prompt or a solver starting from its answer. Solver stages, the copy of the archived gradient fit, engineered weights and certificate constructions are recorded separately for supplementary analysis. They do not participate in the primary counts. `literal_attempts.csv` enumerates every requested array, including an invalid array if one occurred. The scope names in the paired tables denote the new arithmetic graphs and the eight original graph families; both used new literal replies and a shared fitting objective.

Every split uses the same inputs, target, arithmetic, exact-match unit and starting state for each pair of methods. The binary64 oracle is the designated numerical operation or integer recurrence. An exact match requires equality at every component of one predicted example. For the two number sequences it counts individual indices. The raw root mean squared error (RMSE) averages squared errors over all scalar components in the target's native units before taking the square root. The number of examples and scalar components are separate CSV fields. This avoids treating the 6 outputs of a running-sum stream as 6 independent exact examples. `train` means the supplied observations. `dev` is an independent in-range sample except on Fibonacci and triangular numbers, where it means early unseen indices 9–32. `outer` is the value shell for the continuous, arithmetic and list tasks; the integer tasks use indices 33–64. Outer running sums have the same length of six as observed streams. Joint length-and-range tests are separate experiments.

`paired_deltas.csv` preserves every within-setting numeric comparison, the two exact counts, signed difference WSP minus gradient, and strict outcome. `paired_summary.csv` tabulates the counts for each task, architecture, source dataset and the complete benchmark. The pair table and figure use strict comparisons of unrounded scores, including very small differences. We also include the alternative convention that regards an absolute training-loss difference of at most 1e−10 as a tie. RMSE magnitudes are summarized only within a task to avoid pooling unlike outputs. `initialization_deltas.csv` compares each method with the initial weights. `by_method.csv`, `sizes.csv` and `score_overview.csv` give per-method and per-size exact and RMSE summaries plus training loss and counts of fully correct test sets. A per-size median of three starts summarizes each metric separately. A size's median raw RMSE and median exact count may come from different starts.

`optimality.csv` compares each of the four primary endpoints to the smallest training loss among those same four endpoints. It also reports applicable global real-arithmetic training-loss references for the one-hinge and interpolating wide networks. Near the certified real minimum means the absolute difference in training loss is at most 1e−10. Binary64 model execution and real model execution are separately identified. The smallest of four observed losses is a descriptive reference, unavailable to an optimizer in advance. A terminal score on held-out data is always evaluated on the actual returned weights. No oracle chooses a winner separately on different test examples.

From the repository root, run `VECLIB_MAXIMUM_THREADS=1 python focus/endpoints/analyze.py` after `focus/nonconvex/audit.py`, `focus/objective/experiment.py score` and `focus/arithmetic/score.py` have generated their tables. The required native optimizer states are `extension/optimizer/states.npz`. The script re-evaluates these weights with the same per-task reference, error reduction and raw-RMSE routine as the new WSP replies. It checks all original exact counts and validates the split denominators. The generated `figure1.tex`, `paired_table.tex` and `endpoint_tables.tex` can be included directly when their inputs are staged alongside the manuscript. The figure and both typeset tables display the full WSP information-condition names.
