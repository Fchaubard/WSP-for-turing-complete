# Jointly nonlinear-parameter addition and subtraction

The network is a fully trainable dense map with two inputs, a single hidden layer of width 1, 2 or 4, rectified linear activation, and one affine scalar output. It has 5, 9 or 17 scalar parameters. The input-to-hidden and hidden-to-output weights are separately drawn from layer-wise Xavier uniform distributions. Both biases start at zero. Each call exposes the exact same initialized arrays, examples and coordinate support to its two information conditions. All inference uses explicit binary64 scalar products and additions followed by a sum of the weighted hidden units and then the final bias.

## Design

- Use the original paired study's seeds 164, 317 and 583. For each task and seed, reuse its 12 uniform training pairs in the square [-3,3]^2. Every method uses the same 2,048 new central points and 2,048 outer points. Each outer coordinate independently has uniform magnitude on [3,10] and a random sign. References are binary64 input addition or subtraction.
- Request one isolated answer per combination of task, seed and prompt condition. Each of the 12 medium-effort requests to the named hosted model alias gpt-6-astra returns three arrays, ordered by width. Examples-only requests show the common domain and labeled pairs. Formula requests add the target equation. The runner uses a read-only temporary project, a 300-second timeout and disables user configuration. No test observations enter prompts or training. Raw answers, exact prompts, response metadata, prompt/reply hashes and validity by array are archived. The two WSP results in the paper are direct model replies. The additional engineered estimator is separately constructed and labeled.
- Match the objective across both model instructions and both numerical solvers: one half of the mean of the squared training residual divided by max(1, |target|) squared. The WSP prompt uses out-of-range exactness as a secondary goal among equivalent central fits. Neither solver selects checkpoints using held-out outputs. Model calls return three width proposals; the fits at three widths are separate.
- adam_bfgs uses 800 Adam updates at step size 0.02, decays 0.9 and 0.999, denominator offset 1e-8 and gradient norm clipped at 5. The BFGS phase uses full-batch reverse propagation, at most 1,000 iterations and gradient tolerance 1e-14. Keep its result if it improves or ties the final Adam objective. trf_xavier starts from the original draw, uses an analytic residual Jacobian and up to 250 trust-region evaluations at tolerances 4e-15, followed by at most 10 improving least-squares step searches across seven step lengths. Each fit retains its termination reason, evaluation counts and refinement diagnostics. Per-coordinate finite differences and a separately assembled residual Jacobian check the reverse loss derivatives on each initial array.
- The engineered width-one control offsets the linear target by 20 inside the rectifier and cancels the offset outside. This realizes the mathematical map on the bounded real domain and can round differently in binary64. At widths two and four the engineered control computes the difference of the positive and negative parts, with additional width-four units set to zero.
- The nonconvexity check uses the actual stored labels and training inputs, not a surrogate task. For the first hidden unit at endpoint A, use input weight (1,1) or (1,-1), hidden bias 8 and output weight 1. Set the output bias to -8 and other units to zero. Endpoint B doubles this unit's input weights and bias, and halves its output weight. The endpoints implement the same real function. Their parameter midpoint multiplies that hidden unit's active affine output by 9/8 before subtracting 8. The verifier evaluates exact rational losses for all three parameter arrays on every task, seed and width, and separately checks the strict midpoint violation under the archived binary64 evaluator. A mathematical nonconvexity certificate asserts no particular optimizer will fail.

## Files and replay

- fixtures.npz freezes every binary64 training, dev and outer input, label and initial parameter array. scores.csv uses one row per task, size (hidden width), seed, method and split. exact is a count. rmse is raw root mean squared prediction error in target units. train_loss is the scaled half mean squared error on the displayed 12 pairs. n_examples and n_scalars coincide since each input pair yields one scalar.
- fits.npz contains initialized arrays, the two gradient fits and engineered weights. midpoint_witnesses.json stores endpoint vectors, exact-rational losses, binary64 losses and convexity gaps. optimization.json gives the finite-difference test error and stopping diagnostics for all 36 fits.
- Recreate fixtures with the repository numerical Python interpreter and focus/arithmetic/fixtures.py, rerun the gradient fits and certificates with focus/arithmetic/fit.py, and regenerate all scalar metrics from the frozen replies and fits with focus/arithmetic/score.py. Run from the project root. A fresh request to the hosted model is optional and can differ over time; extension/writer/run.py --workers 4 --folder ABSOLUTE_PATH_TO_focus/arithmetic reuses already archived responses by default.
