# What the 60 literal WSP replies contain

From the repository root, run `python focus/coefficients/audit.py` in the published numerical environment. It reads the raw replies, prompts and terminal metadata in `focus/objective/trials/` and `focus/arithmetic/trials/`, then joins the returned arrays to their measured outer predictions in `focus/endpoints/endpoints.csv`. The generated `arrays.csv` indexes every reply by relative path and zero-based index. Beside any `.reply.txt` there is a corresponding `.prompt.txt` and `.meta.json`.

## What was observed

The 60 requests covered ten targets, three initialization seeds per target, and two prompt conditions. Both conditions gave the architecture, exact initial numerical weights, observed training pairs, domain and the same primary scaled squared-error objective as the gradient methods. One also provided the formula. Each request asked for complete JSON arrays of binary64 coefficients, one per width, without tools. Running sum used two widths per reply; every other task used three. All 60 metadata records identify the requested model as `gpt-6-astra` with medium effort and contain one completed final model-message event. None records a tool event. All 174 returned vectors have the required length and finite entries. All 174 differ numerically from the supplied initial vector. Across the vectors, 3,142 of 3,252 scalar entries differ numerically. This measures endpoint changes; the replies supply no intermediate weight iterates. The traces establish which arrays were returned. They do not establish how the model generated each number internally.

## Recoverable structure

- **Addition and subtraction.** Let t = x₁ + x₂ or t = x₁ − x₂, respectively, and let R(t) = max(0,t). At width two, all 12 arrays across the two tasks, two conditions and three seeds contain exactly the identity R(t) − R(−t). For example the examples-only subtraction reply, seed 164, returned `[1,-1,-1,1,0,0,1,-1,0]` (two input-weight rows, two hidden biases, two output gains and the output bias). At width four, eleven replies added inactive units and one duplicated the pair with gains ±½. All 24 matched every one of 2,048 outer outputs. Each of the twelve width-one arrays instead used a single offset gate. Seven used bias 20, enough to implement the mathematical rule over the full bounded real domain, though intermediate rounding can change the binary64 result. The remaining five clipped the rule on part of the domain. None matched every outer output. Compare `focus/arithmetic/trials/738159e5daa8.reply.txt` and `focus/arithmetic/trials/47325749c57b.reply.txt`.
- **Sine, hyperbolic tangent and square.** A scalar network here is an affine term plus a sum of rectified affine terms. Odd parity means f(−x) = −f(x), even parity means f(−x) = f(x). On [−10,10], zero of 18 sine arrays and zero of 18 hyperbolic tangent arrays had exact odd parity; zero of 18 square arrays had exact even parity. For a proof about the real functions represented by the stored binary64 coefficients, the script converts the coefficients to exact fractions, then checks x=0, x=10 and the absolute values of all interior knots. Between consecutive sites the parity residual is affine and its absolute maximum is attained at an endpoint. For sine the median maximum oddness defect across six replies fell from 11.120 at width one to 3.500 at width four and 0.08971 at width sixteen. For the formula-given seed 164 array, the width-one vector `[-0.7098,-2.33627,1.3681,2.25639,1]` gives f(x) = −0.7098x − 2.33627 + R(1.3681x + 2.25639). Its worst oddness defect is 11.26485. The width-sixteen array in the same reply reduces it to 0.11483 and has outer RMSE 0.03220, with zero of 4,096 sine outputs exact. The audit distinguishes exact symmetry in the realized real-valued function, approximate symmetry, and equality with the floating-point function reference. See `focus/objective/trials/ba89053bf8ca.reply.txt`.
- **Running sum, Fibonacci and triangular numbers.** All six width-one running-sum arrays were exactly `[1,1,1]`: previous state plus input, followed by identity readout. The six width-two Fibonacci arrays implement the standard two-coordinate update in two coordinate orders, three arrays of each kind. For example `[1,1,1,0,1,0,0,1]` means the state transition has rows [1,1] and [1,0], the initial state is (1,0), and the readout selects its second coordinate. Five of six width-three triangular-number arrays update the stored triple (Tₙ,n,1) to (Tₙ+n+1,n+1,1); the sixth stores (Tₙ,n+1,1). See `focus/objective/trials/8e104c199f64.reply.txt`, `996a27af198a.reply.txt` and `bbdbf53337e1.reply.txt` in the same directory.
- **Sorting.** Each of the twelve depth-five and depth-six arrays encodes five genuine compare–exchange operations in exact real arithmetic. Eight use the sequence of wire pairs 12, 34, 13, 24, 23; four use 14, 23, 12, 34, 23. The sixth operation, when present, has zero effect. The audit checks each gate’s identity and all 24 rank permutations. In binary64 the residual update can round a difference before adding it, so the two schedules reproduce only 1,096 and 1,091 of 2,048 full outer vectors respectively. Their raw RMSEs are 5.23×10⁻¹⁶ and 4.94×10⁻¹⁶. See `focus/objective/trials/3032794a6ad7.reply.txt`.

## Which widths were exact?

For each task and size below there are six returned arrays across three seeds and the two conditions. Each listed width achieved a completely exact outer sample in all six arrays. Every other tested width achieved zero completely exact outer samples. Addition and subtraction succeeded at widths 2 and 4; running sum at state sizes 1 and 2; Fibonacci at 2 and 3; triangular numbers at 3 and 4. The smooth tasks and sorting had no width with a completely exact outer set. Overall, each literal WSP condition succeeded in 30 of 87 settings. These are observed outcomes over the reported test sets; the algebraic checks above specify the cases with additional structural evidence.
