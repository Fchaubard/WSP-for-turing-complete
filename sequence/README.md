# Sequence benchmarks

All experiments use CPU binary64. Run the following commands from the directory containing this file. The recorded environment used Python 3.12.12, NumPy 2.5.4, and SciPy 1.18.1. Single-threaded BLAS simplifies replication. Library revisions and floating-point reduction order can affect gradient baselines near convergence.

```bash
export VECLIB_MAXIMUM_THREADS=1 OPENBLAS_NUM_THREADS=1
python run.py
python synthesize.py
python robust_sort.py
python robust_control.py
python gauge_control.py
python tanh_recurrence.py
python signed_indices.py
```

Each script saves a correspondingly named JSON file. The main sweep is in `results.json`, and discrete synthesis is in `synthesis.json`. The files include numeric metrics, seed-level outcomes, and fitted or installed parameters. Data generation and seeds are in the scripts.

## Models and training

The prefix-sum RNN uses a zero initial state with transition A, input vector b and readout v. It emits vᵀh after each update h ← Ah + bx. The Fibonacci and triangular models are autonomous linear systems with learned h₀, A and v and emit yₜ = vᵀAᵗh₀ starting at t = 0. Each width-d model stores d²+2d coefficients. The task tables compare widths 1, 2, and 4 for prefix sums and widths 1 through 4 for the autonomous tasks.

The programmed prefix sum installs a single A = b = v = 1 state. The Fibonacci state holds two consecutive Fibonacci numbers, reads the first, and starts at (0,1). The triangular state holds (Tₜ,t+1,1), starts at (0,1,1), and reads the first. Extra coordinates and their connections are set to zero. For a homogeneous linear system the leading Hankel matrix has entries yᵢ₊ⱼ = (vᵀAⁱ)(Aʲh₀) and rank at most d. The first 2×2 Fibonacci and first 3×3 triangular Hankel matrices each have determinant −1. This certifies the minimal dimensions 2 and 3 for these models. A prefix sum needs at least one retained state even if a direct input-to-output wire is allowed, since two histories can end in the same current input with different sums.

Sorting uses a Batcher odd-even merge network. Its ordinary comparator sends (a,b) to (a−u h,b+v h) with h=ReLU(q(a−b)). Its programmed gains (q,u,v) are all one. The sweep truncates the 5-comparator network for four inputs after 3, 4, or 5 gates, with 9, 12, or 15 trainable gains. A separate 3-gain model shares one comparator across every position. Applying that shared block to a freshly generated length-eight Batcher schedule tests numerical and parameter transfer with supplied routing. The 8-item schedule has 19 comparisons. Each scalar ReLU splits its incoming affine cells at most in two, so a g-ReLU DAG has at most 2ᵍ activation patterns. Exact sorting of four reals requires the 24 distinct permutation Jacobians on open ordering cones. Five gates suffice and four cannot in this real-arithmetic affine/ReLU DAG class. Scalar counts refer to the named parameterizations. This bound addresses gate count and does not establish the optimal parameter count over arbitrary architectures. [Batcher, 1968](https://doi.org/10.1145/1468075.1468121)

Every main fit uses the exact same Xavier coefficients for its gradient and programmed branches. Gradient training uses 800 full-batch Adam updates at .02 (global gradient norm capped at 5), followed by BFGS with analytic reverse-mode gradients, norm tolerance 10⁻¹⁴ and a cap of 1,000 iterations. We use half the mean square error. For Fibonacci and triangular numbers each residual is divided by max(1, |target|) before squaring. The five fixed seeds are 101, 202, 303, 404, and 505. Central finite differences check the gradient for all 15 configurations. The maximum scaled component discrepancy was below 10⁻⁸. The robust shared 50-slot DAG control independently checks its gradient and uses the same training protocol. Gradient estimates differ across linear-equivalent recurrent state coordinate systems.

Prefix sum and sort each fit 256 examples with IID uniform inputs on [−3,3]. Independent test sets have 2,048 lists per configuration. OOD coordinates independently choose either sign with magnitude uniform on (3,10]. Prefix sums train on length 8, test on lengths 8 and 32, and compare to sequentially rounded cumulative sums. Sorting trains on 4 values and also tests length 8 in the shared network. Additional sort domains use exact multiples of 2⁻²⁰. Fibonacci and triangle have one deterministic trajectory each. Training fits indices 0 through 8, then tests indices 9 through 32 and 33 through 64. Their reported fit is in-sample across these nine indices. Their labels use unbounded integer recurrences before conversion to float64.

Metrics include exact numeric and bit comparisons per element, whole-vector exact numeric equality, the fraction within one adjacent representable float of the target (using both nearest neighbors), and an 8ε scaled tolerance. Error measures include max absolute error, RMSE and max |error|/max(1,|target|). Signed zeros compare equal for whole-vector numerical equality. All ordinary random evaluation splits passed by the robust program were also bit-for-bit exact.

## Synthesis from training labels

`synthesize.py` infers a smallest tested width for a rational homogeneous recurrence by solving successive leading Hankel systems exactly and verifying every available prefix coefficient. This produces Fibonacci recurrence coefficients (1,1) and triangular coefficients (1,−3,3). Each becomes an installed shift-register RNN with the first d labels as its starting state. For prefix sums, testing all 27 triples over {−1,0,1} leaves two exact sign-equivalent realizations. For sorting, the same 256 training lists contain all 24 orderings. After mapping labels and inputs to ranks, enumeration explores 1, 6, 36, 216, 1,296, and 7,776 possible comparator schedules at successive depths. Twelve schedules work at depth five. The first installs the Batcher network. This search supplies the compare-exchange operation and learns wiring, whereas gradient sorting fits continuous gains on supplied wiring.

## Exact binary64 selection

The compact real-arithmetic comparator can perturb a selected operand because it subtracts and adds rounded differences. Its OOD four-item whole-vector exact score is 1,105/2,048 (53.96%), rising to 2,048/2,048 on the dyadic lattice. `robust_sort.py` implements an alternative on finite operands in [−10,10], with gradual underflow, round-to-nearest ties-to-even, the specified reduction order, and numerical equality of signed zeros.

Write R for ReLU, K=2⁵³⁷ and M=10. Compute r=R(a−b), u=Kr, v=u−R(u−1), B=1−R(1−u), S=1−R(1−Kv), keep=R(1−B−S), and swap=1−keep. Define G(x,g)=R(x−M(1−g))−R(−x−M(1−g)). The outputs are G(a,keep)+G(b,swap) and G(a,swap)+G(b,keep). The implementation shares both products of M with the gate indicators and performs each listed operation in binary64.

For a≤b, u=B=S=0 and keep=1. If a>b, every binary64 operand is an integer multiple of 2⁻¹⁰⁷⁴, so the rounded positive difference is at least that large. If 0<u≤1 then v=u, hence Kv≥1 and S=1. For u≥1, B=1. In this case u is a representable candidate at distance one from the exact value u−1, so its nearest representable value lies between u−2 and u, implying 0≤v≤2. In both positive cases the bounded nonnegative B and S give keep=0. There is no overflow. G copies an operand exactly when enabled and yields zero when disabled. Thus the comparator routes the original values exactly, up to the sign of zero. The unrolled four-input sorter uses 65 ReLU executions. Each shared comparator has 26 affine DAG nodes, 13 ReLUs, 43 explicit edge slots, and 7 nonzero designated biases. The script initializes every edge with a row-specific Xavier draw, initializes the designated biases to zero, and installs the 50 coefficients. Four items yield 250 coefficient occurrences and eight yield 950 if each comparison is stored separately. Only two non-unit magnitudes appear. This construction trades coefficient magnitude and fixed evaluation semantics for an all-binary64 guarantee on the stated bounded domain. A proof of size minimality for that guarantee is open.

The robust program passes 16,900 paired extrema/subnormal/endpoint tests, 250,912 random raw-bits pairs, and 250,912 adjacent representable inputs in each orientation. All nonzero results agree bit-for-bit with independent min/max operations. Ordinary input rows of lengths four and eight pass every reported evaluation split. With K=64 chosen from the minimum separation in the training examples and the same supplied M=10, all ordinary train and random test lists still pass, but descending adjacent inputs (2⁻¹⁰⁷⁴,0) are returned in the wrong order.

## Prefix-sum coordinate control

At d=1 and over the reals, (A,b,v) with zero initial state realizes exactly the same functions as (A,1,C) with C=bv, including C=0. In the original three-scalar coordinates none of the five full Xavier fits is exact on every OOD length-32 list. In the two-scalar model with independent Xavier A,C, four of five fits learn exactly (1,1) and pass everything. Starting from the mapped original initializations (A,bv) yields three of five. Fixing both outside gains to 1 and fitting only Xavier A yields five of five. Thus the experiment includes recurrent BP successes at exact precision with unseen magnitudes and lengths. The manual gain sweep checks c in {1/8,1/2,1,2,8,1.5,3,√2,π,.1} in the programmed realization A=1,b=c,v=round(1/c). The five listed powers of two preserve every OOD list exactly. Each other gain yields zero whole-list exact matches among 2,048 length-32 trials.


## Vanilla tanh recurrence

The supplementary `tanh_recurrence.py` repeats prefix-sum training with the usual elementwise tanh in the state update. Widths 1, 2 and 4 get the same data, optimization budget and five Xavier seeds. The programmed width-one system sets A=1, b=2⁻⁴⁰, v=2⁴⁰. On every tested ordinary stream, scaling keeps the hidden preactivations close enough to zero for the binary64 tanh evaluation to return its argument exactly. All 2,048 outer length-32 lists match, while the trained width-one network has median whole-list equality 0 and median RMSE 0.452. A scale sweep at width one gives whole-list equality 0% at b=1, 2⁻⁸, 2⁻¹⁶, and 2⁻²⁴, 75% at 2⁻³², and 100% at 2⁻⁴⁰. This is a finite-horizon numerical result. In real arithmetic, the hidden tanh values and a fixed linear readout are bounded so the model cannot compute unbounded prefix sums for all lengths. Moreover, an input near the minimum subnormal can round to zero when scaled down. The recorded decimal targets and NumPy binary64 tanh execution determine the tested behavior.


## Signed integer shells

`signed_indices.py` interprets a signed integer n as |n| unary ticks with a supplied direction bit, starting at time zero. Negative ticks apply a backward transition and positive ticks a forward transition. The readout is the first state coordinate. This clock encodes the index outside the RNN. The signed extensions are F₋ₖ=(−1)ᵏ⁺¹Fₖ and Tₙ=n(n+1)/2. Independent oracle labels use integer fast doubling for Fibonacci and the integer product formula for triangular numbers. All seven central integer indices from −3 through 3 are reused as the fit check; extrapolation enumerates all seven integers in each of [−10,−4] and [4,10].

The direct Fibonacci program writes states (Fₜ,Fₜ₊₁) and integer transitions in both directions. The triangular program writes (Tₜ,t+1,1) and forward/backward difference transitions. Each program populates two dense matrices, initial state and readout (12 slots at width 2 and 24 at width 3). The label-only solver infers the minimal tested rational recurrence from the chronological 7-label central sequence, fits (1,1) for Fibonacci and (1,−3,3) for triangular numbers, loads the central stencil as its starting state, and computes the inverse transition algebraically. Both direct and synthesized programs score 7/7 central and 14/14 outer for each task, including bit equality. These are exhaustive counts on the specified integer shells. An additional teacher-forced gradient control receives the correct shift-register width and learns d recurrence coefficients by predicting the next central label from each observed d-label window. Adam followed by BFGS recovers 14/14 shell values in one of five starts for each task. This control exposes the same canonical recurrence structure as the rational solver.
