# Correctly rounded smooth-function audit

The two deployable programs are fixed affine/ReLU DAGs. They read real-valued binary64 coordinates and produce a binary64 output. The sine program covers [-16,16]. Positive self-power covers [0,128], with the endpoint convention 0^0=1. A known finite graph topology and closed-form specification supply the inductive bias. No test examples or target ordinates from the shell enter these writers.

## Run the weights

Only NumPy, `infer.py`, `graph.py` and `programs.npz` are needed at deployment. From this directory:

```python
from infer import predict
predict("sin", [-3.0, 0.0, 3.0, 9.5])
predict("selfpower", [0.0, 0.25, 3.0, 10.0])
```

The interpreter executes explicit additions, subtractions, multiplications and ReLUs in the serialized order. All multiplication operands were checked statically; at least one side is independent of x in each frozen graph, so each product is an affine scaling. No operation reads a bit pattern or calls sin, cos, log, exp, pow, floor or a division primitive. The exported weights and opcodes are shared by the benchmark and predictor. Reassociation or FMA contraction can change their numerical semantics. Out-of-domain inputs are rejected by the public wrapper.

## Findings

| Model | Written scalar slots | ReLUs | Expanded affine coefficient occurrences | Ordinary inner, shell | Challenge result |
|---|---:|---:|---:|---|---|
| 83-stage sine rotation | 500 | 1,506 | 25,395 | 4,096/4,096 and 8,192/8,192 exact | 30,314/30,326 CORE-MATH values on the declared domain; 1,883/1,884 in the shell |
| 84-bit positive self-power | 1,352 | 2,618 | 35,908 | 4,096/4,096 and 4,096/4,096 exact | 446/896 exact beside near-zero rounding transitions |

Both also passed 32,768 independently generated shell values and 8,192 samples drawn with approximately uniform binary exponent, including the subnormal range. All challenge misses were one ULP. The strongest sine program disagrees with MPFR at x=0x1.9239c4bbb44a4p+1 inside the requested shell. The strongest self-power program returns 1 instead of the preceding representable number at x=0x1.8e2e5fb51604cp-60 inside the central domain. See `hard_sin_failures.json` and `counterexamples.json`.

Every written scalar slot is initialized independently as a scalar Xavier-uniform edge. The deterministic compiler replaces all these values. The choice of graph and fixed arithmetic operations embeds a full algorithm. Counts of stored slots omit topology and signs implicit in matrix operations. `programs.json` gives the four or seven structural literals, raw operation count, dynamic graph size, and number of expanded affine coefficient occurrences. That last count charges two scalar coefficients for a sum/difference of two variables (or a gain plus offset) and one for a scale, counting repeated occurrences separately. Dense-layer parameter counts would depend on a separate choice of layout. The sizes establish upper bounds within explicitly chosen architectures.

The sine writer decomposes the angle into binary increments and conditionally rotates a running sine/cosine pair. Its constant tables are generated by small-angle Taylor series and angle doubling. The self-power circuit reduces the mantissa using successive factors 1+2^-j and stored log1p values, forms x log(x) by conditionally summing scaled copies, then exponentiates by selecting precomputed exp(2^k) factors. It reads no shell labels. Both implement copy-if-enabled by a pair of bounded, signed ReLUs. Single-word controls and compensated double-word controls share these algorithmic steps. Related digitwise elementary-function algorithms predate neural networks. [Bajard, Kla and Muller (1994)](https://doi.org/10.1109/12.295857)

`train.csv` records full reverse-mode Adam on all 500 slots of the same largest sine graph, using the same central 1,024 labels, three Xavier starts, 100 updates, batch size 32 and learning rate 0.01. It attained zero exact ordinary shell predictions in each run. Only 2, 2 and 0 slots changed. This narrow-budget diagnostic exposes dead selectors at generic coefficients. A separate central-only odd-polynomial Gauss–Newton fit and globally written Taylor polynomial evaluate in the same arithmetic Horner topology. The polynomial and log/exp series graphs in `sweep.csv` allow products of two input-dependent quantities; they are evaluated separately from the pure ReLU graphs.

## Metrics and external data

MPFR in round-to-nearest-even mode at 53 bits gives each ordinary reference. Independent higher-precision re-evaluation rounded back to binary64 agreed on the audited sets. All values here are normal outputs except the directly routed near-zero sine values, for which the source and rounded result coincide. `correct` and `within1` count exact and adjacent-number successes against MPFR. `worst_ulp`, `max_abs`, and `mae` distinguish accuracy levels. `numpy_equal` counts equality against the local NumPy implementation, while `numpy_ref_equal` counts NumPy versus MPFR. For example, NumPy disagrees with MPFR on 321 ordinary sine shell inputs and 3 ordinary positive self-power shell inputs. The CORE-MATH shell witness has absolute error 1.0842e-19 and relative error 1.3633e-16. Positive self-power transition misses have absolute error 2^-53.

The public external sine hard cases are evaluated from the hash-checked LLVM mirror of CORE-MATH commit `77792c2c3933e950ae6b058e65018376402f0692`. The source header credits Vincent Lefèvre's testlibm worst-case data. We filter to distinct finite values with 0 < |x| <= 16, then take the requested shell subset independently. The distribution includes our measurements and failure witnesses. It fetches the full upstream numeric corpus separately when requested. The LLVM repository is licensed under Apache-2.0 with LLVM exceptions. See [CORE-MATH's corpus description](https://core-math.gitlabpages.inria.fr/worst.html), the [pinned source](https://github.com/llvm/llvm-project/blob/1bfdad8e5c16f98c7a6aa531eb061fd2550ba169/libc/test/src/math/exhaustive/sin.wc), [Lefèvre's hard-case project](https://www.vinc17.net/research/testlibm/) and the [LLVM license](https://github.com/llvm/llvm-project/blob/main/LICENSE.TXT).

## Reproduce

The recorded CPU run used macOS 26.0 arm64 Apple M5, Python 3.13.12, NumPy 2.5.4, gmpy2 2.3.2, MPFR 4.2.2 and GMP 6.3.0. The plot only requires Matplotlib in addition. Run from this directory:

```sh
python run.py                     # polynomial and log/exp arithmetic circuits
python relu.py                    # sine ReLU size and precision sweeps
python relu_power.py              # positive self-power ReLU sweeps
python stress.py                  # exponent, subnormal and near-midpoint challenges
python train.py                   # all-slot same-graph central gradient fits
python hard_sin.py --fetch        # verify pinned public dataset and score it
python export.py                  # rebuild frozen programs
python replay.py                  # check results and concrete misses using the exported weights
python plot.py                    # rebuild paper/smooth_precision.pdf from the CSVs
```

`hard_sin.py --file /path/to/sin.wc` accepts a previously downloaded file with the recorded SHA-256. Corpus download size is about 24.9 MB. The self-power extension covers only its nonnegative real domain. The separate signed-integer self-power experiment is in the original scalar benchmark. Broad tests and explicit misses do not establish a uniform correctly rounded implementation or an optimal model size.
